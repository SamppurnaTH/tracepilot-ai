## Changes between rounds

Round 1 stopped after four recorded cases; the prior process exited during marshmallow without a recorded observation. The exit status was reported as 4 in the handoff, but its original cause is not established. Round 2 preserves those observations and adds pyproject dependency/src-layout support, continued collection after import errors, explicit unchanged-unloadable-file reporting, and outputs for chained tool calls left pending at a phase budget. The runner now persists traces and records per-case exceptions. Round 2 is a harness-fix follow-up after inspecting round 1, not seven untouched holdout attempts.

## Limits

Seven cases, at most one attempt per case per round: a small sample, not a broad benchmark. The projects are public, so older versions of their code or fixes may be in the model's training data; merge dates do not establish a training cutoff. Five bug reports were written from the fix PRs' descriptions (symptom, reproduction and expected result only); two are the real issue text. Projects run without being installed: tests import them from the workspace.
The model is not deliberately supplied the fix commit or its new tests. Study authors selected cases while knowing the fixes; this is model-blinded evaluation, not a double-blind or independently administered study. The inflect issue itself contains a root-cause hint. Passing the upstream tests is bounded evidence, not proof of correctness for every input. A hidden-test pass is distinct from the agent's own verified/approved status.
An attempt is one invocation of the standard investigation workflow, including its built-in fix and reviewer loops; the events preserve each internal round. There is no investigator restart after seeing a hidden score.
Token columns cover the investigator only, not separate reviewer usage. Missing usage after an API error is unknown, not zero. Durations cover the investigation, excluding initial project-image preparation and post-run hidden scoring. Shared-host times are descriptive, not an isolated speed benchmark.
There is no paired plain-agent control in this study, so these outcomes do not establish an advantage over another coding agent. Selected public Python libraries do not represent all private repositories or production incidents.
